# codex-round1-engineering (Codex gpt-5.6-terra, read-only, 2026-10-01)

Verbatim output. Every finding is resolved in docs/designs/realstage.md → "Outside Voice Round".

1. **P1 — Budget Lock / sketch / model selection:** Credit math is internally impossible. Budget assumes 1 credit/image, while the wireframe shows 6 + 4 + 5 credits per three-model fan-out. At those displayed rates, 12 library images cost 60 credits—before bake-off, demo, or judges. The fixed IDs are premium, contradicting “cheapest standard tier.” Fix: probe exact costs first; choose either fixed cheap models or the premium IDs, then allocate from actual costs. Do not deploy live generation unless the post-library remaining balance supports it.

2. **P1 — Budget Lock vs E2:** “Global cap = 15 credits” is ambiguous and contradictory. If the ledger counts all generation reservations across days, library, bake-off, and video consume it before judges. If it counts only public calls, it does not protect the 50-credit ceiling. Fix: separate immutable build allocation, demo allocation, and a production-only 15-credit reserve with distinct ledger tags and a hard check against actual remaining quota.

3. **P1 — E2 budget ledger:** Cloudinary tag queries plus per-instance 60-second caches are not an atomic reservation system. Concurrent Vercel instances can all observe the same remaining budget and overspend by far more than one call. Fix: remove public live generation under a $0 cap, or use an actual atomic store. “Reservation assets” only record overspend after competing requests have already passed.

4. **P1 — Kit export / T-E8:** `create_zip` cannot be the must-ship download path on a Free account: Cloudinary allows archive creation but blocks delivery of ZIP/archive formats by default. The proposed fallback is therefore likely the normal path, not an exception. Fix: make four direct file downloads the primary export; treat ZIP as optional only after a real Free-account delivery test. [Cloudinary Upload API reference](https://cloudinary.com/documentation/image_upload_api_reference)

5. **P1 — Relight flow:** `image_to_image` requires both `prompt` and `reference_images`. The plan materializes a composite but never specifies sending it as `[1]` by managed `asset_id` or URL, nor does its prompt refer to `[1]`. The API call will fail or not perform the claimed edit. Fix: define the exact request: materialize composite → pass its managed `asset_id` in `reference_images` → prompt explicitly references `[1]` → persist the task result. [Cloudinary Image Generation docs](https://cloudinary.com/documentation/image_generation_addon)

6. **P1 — Upload/cap security:** `/api/sign {sessionId}` trusts a browser-chosen session ID, and a signed upload signature is replayable during its validity window. A pre-sign cap check does not cap uploads; an attacker can obtain or reuse signatures and drain storage/transformation credits. Deferring session controls makes the public upload path unsafe. Fix: sign one server-generated opaque session and one fixed unique public ID per upload, reserve upload capacity before signing, and keep public uploads disabled after recording if no atomic counter exists.

7. **P1 — Retention / TODOS:** “Stored for 7 days, then deleted” is false. Tags do nothing without cleanup, and cleanup cron was deferred. This also invalidates storage budgeting and creates a privacy problem for user photos. Fix: ship the daily Vercel Hobby cron or remove the retention promise and keep the app private after judging. Hobby supports one daily cron at no cost. [Vercel cron limits](https://vercel.com/docs/cron-jobs/usage-and-pricing)

8. **P1 — Cloudinary Free-plan budget:** The plan still has no executable transformation/storage/bandwidth budget. `api.usage() >= 20/25` is merely a late stop condition, not a cap derived from expected per-user costs. Every unique cutout, composite preview, materialized final, four exports, and delivery variant consumes quota; cached URLs only avoid repeat transformation charges. Fix: allocate explicit transformation credits for library, demo, and a bounded number of judge uploads; cap uploads accordingly. [Cloudinary billing and transformation counting](https://cloudinary.com/documentation/billing_and_plans)

9. **P2 — Cutout validation:** Alpha coverage after `e_trim` is a bad quality gate. A legitimate opaque rectangular jar/package can occupy >95% of its trimmed bounds and be rejected; a poor removal can also pass. Fix: compute coverage before trim, or only reject no-alpha/full-frame results and require a manual “cutout looks wrong” retry path.

10. **P2 — 1K resolution rule / kit claims:** A 1024² stage cropped to 819×1024 and scaled to 1080×1350 is upscaled. The 9:16 output is padded blur, not a channel-ready scene. This contradicts the earlier “no upscaling” rationale and weakens the marketplace claim. Fix: generate vertical and 4:5 library stages deliberately, or label these as social previews rather than high-quality exports.

11. **P2 — Background-removal verification:** Opening one `e_background_removal` URL is not verification of the actual pipeline: remote upload of a derived URL, 423 handling, PNG alpha preservation, `e_trim`, and re-upload as `_cut` are separate contracts. Cloudinary documents 423 for first on-the-fly generation and 420 for incoming processing. Fix: make one full end-to-end materialization test the first gate, including retry and final asset dimensions. [Cloudinary background-removal docs](https://cloudinary.com/documentation/background_removal)

12. **P2 — Strategic scope:** Pixel-Lock, Sharp erosion, Sobel calibration, Admin-ledger accounting, archive generation, structured metadata, live three-model fan-out, mobile states, and 38 planned tests are not a scope reduction. They are a fragile platform project with three days remaining. The default experience is a curated-background compositor, while the expensive generative path may be paused for judges—weak evidence for Track 2.

13. **P2 — Trust claim / UX:** “Hold to see your original” swaps the whole staged image for a bedsheet photo. It does not demonstrate that product pixels were preserved at the same geometry, and it makes the “real pixels locked” proof easy to challenge. Fix: use a localized before/after wipe over the product bounding box, or drop the proof claim and state the compositing limitation plainly.

14. **P3 — Generated-stage lifecycle:** The generation API automatically adds `text-to-image`/`image-to-image` tags and provenance context, but the plan never defines how generated outputs receive `stage`, `lib`, `session-*`, expiry, and authored geometry. Without an upload preset or post-task update, `/api/state` will not find them. Fix: specify a target upload preset or a single post-completion metadata update before exposing a card. [Cloudinary Image Generation docs](https://cloudinary.com/documentation/image_generation_addon)

Recommendation: cut to upload → cutout → three curated generated stages → four individual downloads, and disable public relight/fan-out, because the current plan cannot guarantee its credit ceiling or its must-ship ZIP path.
